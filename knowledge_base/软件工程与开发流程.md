# 软件工程与开发流程

## 1. 典型开发流程
需求分析 → 方案设计 → 编码实现 → 测试验证 → 发布上线 → 运维监控 → 迭代改进。
每个阶段都有产出物：需求文档（PRD）、设计文档、代码与提交记录、测试报告、发布说明。

## 2. 需求与设计
- 需求要明确"做什么"和"为谁做"，包括功能需求与非功能需求（性能、安全、可用性）。
- 用户故事格式：作为<角色>，我希望<功能>，以便<价值>。
- 验收标准（Acceptance Criteria）：可验证的完成条件。
- 设计文档常见内容：背景、目标、总体架构、模块划分、接口定义、数据模型、异常处理、风险与取舍。

## 3. 版本控制（Git）
- 基本概念：工作区、暂存区、本地仓库、远程仓库。
- 常用命令：
```bash
git init                       # 初始化仓库
git clone <url>                # 克隆远程仓库
git status                     # 查看改动
git add .                      # 添加到暂存区
git commit -m "feat: 新增登录接口"   # 提交
git pull --rebase              # 拉取并变基
git push                       # 推送到远程
git branch feature/login       # 新建分支
git switch feature/login       # 切换分支
git merge main                 # 合并 main 到当前分支
git log --oneline --graph      # 查看历史
git diff                       # 查看未暂存的改动
git stash                      # 临时保存改动
```
- 分支模型：主干开发 + 短生命周期特性分支；发布分支与热修复分支（hotfix）视团队规模而定。
- 提交信息规范（Conventional Commits）：feat / fix / docs / refactor / test / chore。
- 冲突处理：先了解双方改动意图，再手动合并，不要盲目选择"全部接受"。

## 4. 代码评审（Code Review）
- 目标：发现缺陷、统一风格、传播知识，而不是挑刺。
- 关注点：正确性、边界条件、异常处理、可读性、性能、安全、测试覆盖。
- 最佳实践：小批量提交（建议单次评审 400 行以内）、写清改动背景、及时响应。
- 评审意见分级：阻塞（必须改）、建议（可讨论）、疑问（求解释）。

## 5. 测试
- 测试金字塔：单元测试（最多）→ 集成测试 → 端到端测试（最少）。
- 单元测试：验证单个函数/类，速度快、定位准。
- 集成测试：验证多个模块协作，如接口+数据库。
- 端到端测试：从用户视角验证完整流程。
- TDD（测试驱动开发）：先写失败的测试 → 实现 → 重构。
- 其他类型：回归测试、性能测试、安全测试、冒烟测试。
- 好测试的特征：独立、可重复、快速、有明确断言、一个测试只验证一件事。

## 6. CI/CD 持续集成与持续交付
- CI：每次提交自动构建 + 跑测试，尽早发现问题。
- CD：自动部署到测试/生产环境，减少人工操作失误。
- 流水线典型阶段：拉代码 → 安装依赖 → 静态检查 → 单元测试 → 构建制品 → 部署 → 冒烟测试。
- 部署策略：
  - 蓝绿部署：两套环境切换，回滚快。
  - 灰度/金丝雀发布：先放量小部分用户，观察指标再全量。
  - 滚动发布：逐步替换实例，成本低但回滚较慢。
- 制品与版本：构建产物要可追溯（版本号 + 提交哈希）。

## 7. 代码质量
- 命名：见名知意，避免缩写歧义。
- 函数：短小、单一职责，参数不宜过多。
- 原则：DRY（不要重复）、KISS（保持简单）、YAGNI（不做用不到的功能）、高内聚低耦合。
- 注释：解释"为什么"而不是"是什么"；公共接口写文档注释。
- 静态检查：Lint（风格与潜在错误）、类型检查、格式化工具（自动统一风格）。

## 8. 版本号与发布
- 语义化版本（SemVer）：主版本.次版本.修订号。
  - 主版本：不兼容的变更。
  - 次版本：向后兼容的新功能。
  - 修订号：向后兼容的缺陷修复。
- 维护 CHANGELOG，记录每个版本的新增、修复、破坏性变更。
- 发布前检查：测试通过、文档更新、数据库迁移脚本、回滚方案。

## 9. 常用协作与文档工具
- 需求与任务：Jira、Trello、GitHub Issues。
- 文档：Markdown + 代码仓库（文档即代码）、Confluence、语雀。
- 接口文档：OpenAPI/Swagger、Postman 集合。
- 沟通：站会同步进度与阻塞项，评审会讨论方案取舍。
