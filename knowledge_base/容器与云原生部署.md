# 容器与云原生部署

## 1. 为什么用容器
- 容器把应用与依赖一起打包，解决"在我机器上能跑"的环境差异问题。
- 与虚拟机相比：共享宿主机内核，启动秒级、体积小、资源开销低。
- 镜像（Image）是只读模板，容器（Container）是镜像的运行实例，仓库（Registry）用于分发镜像。

## 2. Docker 常用命令
```bash
docker pull nginx:1.25                 # 拉取镜像
docker images                          # 查看本地镜像
docker run -d --name web -p 8080:80 nginx:1.25   # 后台运行并映射端口
docker ps -a                           # 查看容器（含已停止）
docker logs -f web                     # 实时查看日志
docker exec -it web bash               # 进入容器
docker stop web && docker rm web       # 停止并删除容器
docker rmi nginx:1.25                  # 删除镜像
docker system prune -a                 # 清理无用镜像/容器（谨慎）
docker inspect web                     # 查看容器详细信息（IP、挂载、环境变量）
```

## 3. Dockerfile 编写
```dockerfile
FROM python:3.12-slim

WORKDIR /app

ENV PYTHONUNBUFFERED=1 PIP_NO_CACHE_DIR=1

COPY requirements.txt .
RUN pip install -r requirements.txt --no-cache-dir

COPY . .

EXPOSE 8000
HEALTHCHECK CMD curl -f http://localhost:8000/health || exit 1
CMD ["python", "-m", "uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```
- 分层缓存：先 COPY 依赖清单再 COPY 源码，改代码时不必重装依赖。
- 多阶段构建可显著减小镜像体积（构建阶段装编译工具，运行阶段只带产物）。
- 使用 .dockerignore 排除 .git、__pycache__、node_modules 等无关文件。
- 不要用 root 运行应用，可在 Dockerfile 中创建普通用户并 USER 切换。

## 4. 数据卷与网络
```bash
docker run -d -v /data/mysql:/var/lib/mysql mysql:8      # 挂载数据卷，容器删除数据仍在
docker run --name db -e MYSQL_ROOT_PASSWORD=secret -d mysql:8
docker network create app-net
docker run -d --network app-net --name api myapi:1.0     # 同网络可用容器名互访
```
- 容器内数据默认随容器删除而丢失，数据库、上传文件必须挂载卷。
- 端口映射 `-p 宿主机端口:容器端口`；只对内网提供服务时不必映射到宿主机。

## 5. Docker Compose 编排
```yaml
services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://user:pass@db:5432/app
    depends_on:
      - db
    restart: unless-stopped

  db:
    image: postgres:16
    environment:
      - POSTGRES_PASSWORD=pass
      - POSTGRES_USER=user
      - POSTGRES_DB=app
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```
```bash
docker compose up -d          # 启动全部服务
docker compose logs -f api    # 查看某个服务日志
docker compose down           # 停止并删除
docker compose up -d --build  # 重建镜像再启动
```

## 6. Kubernetes 基础概念
- Pod：最小调度单元，通常一个 Pod 跑一个容器。
- Deployment：声明副本数与滚动更新策略，负责维持 Pod 数量。
- Service：给一组 Pod 提供稳定访问入口（ClusterIP/NodePort/LoadBalancer）。
- Ingress：七层入口，按域名/路径转发到不同 Service，并配置 TLS。
- ConfigMap/Secret：注入配置与敏感信息；Volume/PVC：持久化存储。
- 常用命令：
```bash
kubectl get pods -n prod            # 查看 Pod
kubectl describe pod api-xxx -n prod # 排查调度/镜像/探针问题
kubectl logs -f api-xxx -n prod      # 查看日志
kubectl rollout restart deploy/api   # 重启部署
kubectl rollout status deploy/api    # 查看滚动更新进度
kubectl apply -f deploy.yaml         # 应用配置
```
- 健康检查：livenessProbe 探活失败会重启容器，readinessProbe 未通过则不接流量。

## 7. Nginx 反向代理与部署
```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 60s;
    }

    location /static/ {
        alias /var/www/static/;
        expires 7d;
    }
}
```
- 用 certbot 申请证书后 Nginx 会自动改写为 443 配置并做 80 → 443 跳转。
- 常见错误：502（后端未启动或地址写错）、504（后端处理超时，调 proxy_read_timeout）。

## 8. 上线流程与回滚
- 构建：CI 中跑测试 → 构建镜像 → 打 tag（版本号+git commit）→ 推送到镜像仓库。
- 发布：拉取新镜像 → 滚动更新（先起新实例，健康后再停旧实例）→ 观察日志与监控。
- 回滚：镜像 tag 回退或 `kubectl rollout undo deploy/api`，数据库变更要提前设计兼容方案。
- 灰度与蓝绿：按比例放量或两套环境切流量，降低发布风险。
- 上线后观察：错误率、响应时间 P95/P99、CPU/内存、连接数、日志告警。

## 9. 常见排查思路
- 容器起不来：`docker logs` 看启动报错；配置错误常见于环境变量与挂载路径。
- 容器内访问不到外部：检查网络模式与 DNS；容器内不要用 localhost 访问宿主机服务。
- 镜像过大：多阶段构建 + slim/alpine 基础镜像 + 清理缓存。
- 内存被 OOM Kill：`kubectl describe pod` 看 Reason: OOMKilled，调整 limits 或排查内存泄漏。
- 磁盘写满：清理日志与悬空镜像（docker system df 查看占用）。
